# Telegram и оформление

Дата: 29 октября 2026.

## Где была сессия

Одна сессия живёт в `App`. Её получают профиль, заказы и оформление. Отдельного входа на каждом экране нет. Открытие и закрытие оформления сессию не создаёт заново.

При перезагрузке внутри Telegram приложение снова отправляет сырой `initData` на `POST /api/auth/telegram`. Идентификатор в `localStorage` не записывается. Тестовая роль `dev` не считается входом Telegram.

## Почему оформление теряло покупателя

SDK не загружался до чтения `initData`. Вне Telegram `initData` нет, и поля имени оставались пустым вводом. Сервер уже проверял подпись, но клиент мог не дойти до этого запроса.

Теперь при запуске вызываются `ready()` и `expand()`. Сырой `initData` уходит на существующий endpoint. Если его нет, фиктивная Telegram-сессия не создаётся.

## Проверка initData

`server/index.js`, `verifyInitData`:

- секрет HMAC из токена бота и строки `WebAppData`
- сравнение hash через `timingSafeEqual`
- `auth_date` не старше 24 часов
- `user.id` читается из исходной JSON-строки, без округления числа
- username необязателен и не является ключом

Клиентский `tgId` без подписи отвечает 401. В production `POST /api/auth/dev` по-прежнему 404.

## Что видно в оформлении

Проверенная сессия показывает блок «Ваш Telegram»: имя, `@username` или «Username не установлен», Telegram ID. ID не редактируется. Телефон не требуется: заказ привязан к ID из сессии.

Пока вход проверяется, строка «Подтверждаем Telegram.» Если подписи нет: «Откройте магазин через Telegram, чтобы подтвердить заказ.» Кнопка «Открыть через Telegram» появляется только при `TELEGRAM_BOT_USERNAME` из конфигурации. Выдуманной ссылки нет.

Просроченная или неверная подпись и обрыв сети оставляют текст «Не удалось подтвердить вход через Telegram. Откройте приложение заново.» Корзина не очищается.

## Оплата

`/api/config` отдаёт `payments: ["cash"]`. В панели включены только наличные. «Карта при получении» и «Другое» видимы и выключены. Выбранный `cash` уходит в существующий `POST /api/order/payment`. Сумму считает сервер. Онлайн-оплата не имитируется.

## Что не является PASS

`getMe` этим проходом не подтверждался. Живой вход через бота и живые заказы не проверены.
