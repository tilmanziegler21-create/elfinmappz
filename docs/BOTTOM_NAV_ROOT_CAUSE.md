# Почему пропадал нижний бар

Дата: 29 октября 2026.

## Причина

Бар не размонтировался при смене вкладок. Он пропадал по двум правилам.

1. `data-product` становился `true` от любого `productId`, даже если на экране уже корзина, заказы или профиль. CSS прятал `.nav` через `display: none`.
2. Бар стоял `position: absolute` внизу `.stage`, а высота приложения была `100dvh`. В Telegram видимая высота приходит отдельно через `viewportHeight` и может быть меньше `100dvh`. Бар оставался ниже видимой области. Закрытая панель оформления лежит поверх всего слоя `z-index: 24`, бар был на `z-index: 2`.

Случайный большой `z-index` не добавлялся.

## Правило

| Экран | Бар |
| --- | --- |
| Главная, каталог, корзина, заказы, профиль | виден |
| Товар | скрыт, как и раньше |
| Открытое оформление | скрыт, клики не принимает |
| Оформление закрыто | тот же узел снова виден |

Бар закреплён в корне `.stage` и не входит в анимацию смены экрана. Высота оболочки берётся из `Telegram.WebApp.viewportHeight`, когда Mini App его отдаёт. В обычном браузере остаётся `100dvh`. Нижний отступ берётся из `contentSafeAreaInset` или `safeAreaInset`, иначе из `env(safe-area-inset-bottom)`.

Панель оформления ограничена этой высотой, чтобы кнопка закрытия не уезжала за край.
